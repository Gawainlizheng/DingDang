# DingDang · Windows 文件管理器

首版为 Windows x64 内测。支持本地磁盘和常用位置、地址栏、排序、多选、双击打开、新建、重命名、应用内复制／剪切／粘贴和回收站。没有 AI、联网功能、Office 编辑器或自动更新。

## 开发和打包

多标签仅浏览文件夹。使用 `Ctrl+T` 新建、`Ctrl+W` 关闭、`Ctrl+Tab` 切换；`Alt+←`、`Alt+→`、`Alt+↑` 分别后退、前进和返回上一级。右键文件或列表空白处可打开应用内菜单，复制和剪切可跨标签粘贴。

在 Windows 上使用 Node.js 22、npm 和 VS Code。进入项目目录后执行：

```powershell
npm ci
npm test
npm start
npm run package:win
```

安装包输出到 `release/`。使用私下渠道交给试用者；用户无需安装 Node.js，可按当前用户安装。内测包未签名时 Windows 可能提示风险；不要关闭系统防护。安装后文件操作不需要联网。

## 二次开发指南

### 示例一：追踪“复制文件”

1. 在 `src/ui.tsx` 选中文件后点击「复制」，切换目录再点击「粘贴」；前者仅记录应用内剪贴板，不触碰磁盘。
2. 粘贴调用 `window.files.copyItems(所选路径, 目标目录)`，接口定义见 `src/contracts.ts`，预加载桥仅将调用转发到固定频道。
3. `src/main.ts` 验证调用来自可信顶层页面；`src/service.ts` 校验路径并逐项独占创建目标。同名不覆盖，目录复制中断时保留已复制内容并报告失败。
4. 在两个临时文件夹各放一个同名文件，再额外复制一个不同名文件。结果应分别显示失败和成功，目标同名文件内容不变。自动化示例见 `tests/files.test.ts`。

### 示例二：新增只读文件详情面板

1. 在 React UI 中新建组件，接受 `Entry | undefined`。先用现有条目字段展示名称、类型、修改日期和大小，不加 IPC，也不在渲染端读取磁盘。
2. 在文件列表右侧渲染该组件，传入当前的 `single`；无选择和多选显示「请选择一个文件」。不可用字段显示「—」。
3. 把需要单测的格式化函数独立为纯函数，在测试中传入文件、目录和缺失元数据；手动验证切换选择后详情随之更新。若未来需要读取新元数据，再为契约、桥接和服务分别添加一个只读方法及路径校验。

## 内测验收

- 在没有开发工具的 Windows x64 电脑上验证下载安装、断网启动和卸载。卸载后检查用于测试的文件仍在。
- 使用临时目录验证地址栏、前进／后退、排序、批量冲突、同盘和真实跨盘文件及目录移动。单测只模拟跨盘回退，不代替双盘测试。
- 使用临时测试文件验证权限拒绝、文件占用、回收站不可用时的失败提示；正常移入回收站后，用系统回收站恢复文件。不要用真实用户资料做验收。
- 首版路径限定本地盘符，不支持直接输入 UNC 和设备路径；复制和移动不跟随文件链接。跨盘目录移动先复制后清理，不是原子操作；有失败时按逐项提示核对两端。
